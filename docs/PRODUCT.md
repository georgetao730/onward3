# Onward3 — Product Definition

## Mission

Help Web2 developers become Web3 builders through a structured, visual, and interactive learning experience.

## Primary User

A Web2 software engineer who:

- can already code and understands normal web architecture;
- is curious about Web3 but does not know where to start;
- wants mental models rather than crypto jargon;
- prefers building and experimenting over watching long courses.

## Core Promise

**From Web2 Developer to Web3 Builder.**

A learner should always know:

1. what to learn next;
2. why the concept exists;
3. how it differs from Web2;
4. how it works under the hood;
5. how to experiment with it;
6. what to build with it.

## V0.1 User Journey

Home → Start Learning → Roadmap → Lesson → Interactive Demo → Quiz / Takeaways → Next Lesson

## V0.1 Pages

- `/` — Landing page
- `/roadmap` — Web3 learning roadmap
- `/learn/[slug]` — Lesson page
- `/playground/wallet` — Wallet Playground
- `/about` — Product story

## Lesson Template

Every lesson should follow the same learning model:

1. **What is it?**
2. **Why does it exist?**
3. **How does it work?**
4. **Web2 analogy**
5. **Visual / interactive demo**
6. **Code example** (when useful)
7. **Key takeaways**
8. **Quick quiz**
9. **Next lesson**

## V0.1 Scope

### Must Have

- Landing page
- Roadmap
- Reusable lesson layout
- 10 foundation lessons
- Wallet Playground
- Local learning progress
- Responsive design
- Basic SEO / metadata
- Production deployment

### Explicitly Not V0.1

- Authentication
- Database
- CMS
- Payments
- AI tutor
- Community / comments
- Job board
- Complex backend services

## Design Direction

Onward3 should feel like a modern developer product, not a speculative crypto website.

Principles:

- clean typography;
- generous whitespace;
- strong information hierarchy;
- subtle borders and code-inspired details;
- restrained motion;
- no token-price aesthetics, neon overload, or crypto clichés.

Reference mood: modern developer documentation and tools.

## Success Criteria for V0.1

V0.1 is successful when a Web2 developer can land on the site, understand the promise within seconds, follow the first learning path, complete a lesson, interact with the Wallet Playground, and know what to learn next.
